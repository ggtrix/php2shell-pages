Your hospital website and patient portal may be running the PHP version attackers are targeting.

PHP2Shell is a critical, unauthenticated remote code execution flaw in the PHP core. It lets attackers run code on any internet-facing system serving PHP requests, before application-level protections even activate.

Because the flaw is in the PHP runtime itself, fully updated applications stay exposed until PHP is patched to 8.2.35, 8.3.36, 8.4.27 or 8.5.12, or an equivalent vendor backport. Exploitation attempts were reported before the official patches were released.

Where PHP runs in healthcare

Your hospital website and patient portal are often the ones exposed

Many healthcare organizations rely on PHP for their most public-facing systems. A single vulnerable instance can expose protected health information, disrupt care operations and create HIPAA compliance risk.

Patient portals

Records, results and messages behind one login page.

Appointment scheduling

Booking forms that hold names, dates and reasons for visit.

Telehealth interfaces

Visit pages and intake forms that sit in front of live consultations.

Provider directories

Search tools often built on older CMS stacks.

Hospital websites

Main hospital sites, location pages and campaign microsites.

Protected health information can be exposed through one compromised server.

Care operations can be disrupted if scheduling or telehealth goes down.

HIPAA compliance risk follows any unpatched system that touches patient data.
